## Classification key

| Label | Meaning |
|---|---|
| `portable` | Content works as-is for Hermes — pure coding standards or workflow prose with no Claude-specific syntax |
| `adapt` | Minor edits needed — Claude tool name mentions, `mcp__` prefix references, or Claude Code-specific phrasing that needs generalising |
| `hermes-variant` | Needs a Hermes-specific version — different flow, different scope, MCP-bound skills, or skills whose entire purpose is Claude-executor plumbing |

## Precedence inspection — HERMES.md vs CLAUDE.md

### Method

Direct source inspection of `prompt_builder.py` at:

```
/opt/hermes-venv/lib/python3.11/site-packages/agent/prompt_builder.py
```

Key function: `build_context_files_prompt` (line 1426).

### Finding

Hermes uses a **first-match-wins, one-file-only** strategy for project context files. The
lookup order is (lines 1429–1433):

```
1. .hermes.md / HERMES.md  (walk from cwd up to the git root — not cwd-only)
2. AGENTS.md / agents.md   (cwd only)
3. CLAUDE.md / claude.md   (cwd only)
4. .cursorrules / .cursor/rules/*.mdc  (cwd only)
```

**When both `HERMES.md` and `CLAUDE.md` exist in the same directory, `HERMES.md` wins and
`CLAUDE.md` is not loaded.** Only one project context file is injected per session.

A key asymmetry: `HERMES.md` is discovered by walking upward from cwd to the git root (the
`_find_hermes_md` function, lines 92–110), while `CLAUDE.md` is cwd-only. This means a
`HERMES.md` at the repo root will be found even when the agent is run from a subdirectory —
`CLAUDE.md` in the same subdirectory would only be found if the working directory is exactly
the directory containing it.

### Current executor behaviour

The Hermes executor (`runtime/executors/hermes/src/index.ts`) currently spawns:

```
hermes chat --query <briefing> --quiet --ignore-rules
```

The `--ignore-rules` flag sets `HERMES_IGNORE_RULES=1` (via `hermes_cli/main.py` line 1451),
which maps to `AIAgent(skip_context_files=True)` (`cli.py` lines 4555–4556). With
`skip_context_files=True`, `build_context_files_prompt` is never called — **neither
`HERMES.md` nor `CLAUDE.md` is loaded**, regardless of which files exist in the working
directory.

### Implication for this feature (T7)

T7 drops `--ignore-rules` and adds a Phase 3.5 that copies `<mgmtRoot>/HERMES.md` →
`<implDir>/HERMES.md` before spawning the agent. Once `--ignore-rules` is removed:

- `HERMES.md` in the impl dir will be found first (lookup order position 1).
- Any `CLAUDE.md` in the same directory will be silently skipped (lookup order position 3,
  never reached after HERMES.md matches).
- No co-existence conflict arises: the executor intentionally places `HERMES.md` in the
  cwd, not `CLAUDE.md`.

This behaviour was confirmed by code inspection and is consistent with the technical design's
assumption that HERMES.md and CLAUDE.md are written to separate executors' working directories
and never coexist in the same cwd at the same time.

### Reproduction note

Spawning a live session to observe loading was not performed. The Hermes CLI is available at
`/usr/local/bin/hermes` (version confirmed via `hermes --help`), and the source code at
`/opt/hermes-venv/lib/python3.11/site-packages/agent/prompt_builder.py` is directly readable
and definitively answers the precedence question. A live reproduction would add no new
information beyond what the code already states.
