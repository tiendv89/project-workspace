# v001 — initial schema

**Feature**: `m3-agent-chat`
**Date**: 2026-06-06
**Migration file**: `hermes-agent/workflow_gateway/migrations/001_initial_schema.sql`

## Tables created

### `schema_migrations`
Internal migration tracker — records which SQL files have been applied. Used by
`workflow_gateway/db/store.py:init_db()` to run pending migrations at startup.

### `sessions`
One row per agent conversation session. Created by `POST /api/v5/create_session`.
Key columns:
- `id` — `sess_<32 hex>` format, generated by `secrets.token_hex(16)`.
- `workspace_id`, `feature_id` — TEXT slugs; cross-DB reference to the workspace
  database. No FK enforced (cross-database).
- `title` — initially NULL; set by the gateway when the first user message arrives
  (truncated to 60 chars). Used for the session history list in v2.
- `archived` — soft-delete flag; archived sessions are hidden from the history list.
- `metadata` — JSONB for extension without schema changes.
- All timestamps are `DOUBLE PRECISION` (Unix epoch seconds) to match hermes internals.

### `messages`
One row per message in a session. Append-only in normal operation.
- `role`: `user | assistant | tool`
- `active`: `false` for messages pruned from the context window (soft-delete).
- `tool_calls`, `reasoning_details`, etc. stored as serialised text/JSON for
  compatibility with multiple LLM provider shapes.

## Indexes
- `sessions`: on `source`, `started_at DESC`, `user_id`. The
  `(workspace_id, feature_id, started_at)` compound index is added in v002
  (m3-agent-chat-v2) to support the session history list query efficiently.
- `messages`: on `(session_id, created_at)` and `(session_id, active, created_at)`
  for conversation replay and context-window reconstruction.

## Design notes
- `AIAgent` (hermes core) is instantiated with `session_db=NoOpSessionDB()` so it
  does not write to its own SQLite. All persistence is owned by the gateway store.
- The `schema_migrations` table pattern mirrors workflow-backend's migration runner.
- No FK across databases — `workspace_id`/`feature_id` integrity is enforced in
  application code (gateway validates both values against workflow-backend before
  creating a session).
